## 2. Findings by severity

### High

**H1. Clearing a controlled temporal field shows the old value, and DateField/DatePicker submit it (DateField, DatePicker, TimeField, DateRangePicker)**
- **Where:** `fields.mjs:317-318` (`dateOrUndefined` maps `''`/`null` to `undefined`), passed as `value` at `:784`, `:912`, `:850` and `:998`. TimeField also uses `value ?? formValue` at `:844` and `:869`.
- **Why:** RAC treats `value: undefined` as uncontrolled and falls back to the internal state it captured at mount. RAC's convention for "controlled and empty" is `null`.
- **Reproduction:** render `<Form><DateField name="df" value={v} onChange={…}/></Form>` with `v='2026-01-02'`, then `v='2026-03-04'`, then `v=''`.
  - DateField and DatePicker display 1/2/2026 (the mount value, not even the last one), and FormData is `df=2026-01-02`.
  - TimeField with `''` displays 10:15 AM but submits `''`. With `null` it submits a stale `11:45`.
  - DateRangePicker displays the old range and submits empty strings.
- **Also:** a user clearing the field calls `onChange(undefined)`, so the documented controlled pattern flips the component to uncontrolled, with React and RAC warnings.
- **Verified by:** jsdom probe.
- **Fix:** when `value !== undefined`, map `''`/`null` to `null` for RAC, and serialize a cleared value as `''` (or allow `null` in the types). Add controlled update and clear tests for all four families.

**H2. A `required` CheckboxGroup submits with nothing checked under the default `native` Form (CheckboxGroup)**
- **Where:** `src/components.mjs:90` (`required = false`) and `:108` (`isRequired: required`). RAC's `useCheckboxGroupItem.mjs:58` uses `isRequired: props.isRequired ?? state.isRequired`, so the explicit `false` from Mux overrides the group's `required`.
- **Reproduction (Chromium):** `<Form><CheckboxGroup name="alerts" required>…two Checkbox…</CheckboxGroup><button/></Form>`, then click submit. The form submits `[]`, no checkbox is `required`, and no error appears. The same group with raw RAC `Checkbox` children blocks submission and shows "Please tick this box…". `aria` mode matches RAC, which never blocks there.
- **Fix:** default `required` to `undefined` in `Checkbox` and pass `isRequired: required` only when it is defined. Add a test that the submission is blocked; the current test at `fields.test.mjs:1152` only checks `data-required`.

**H3. A single Escape closes the suggestions and also wipes the typed text (Autocomplete)**
- **Where:** `fields.mjs:1205-1225`. Autocomplete uses a bare `AriaInput` inside `AriaSearchField`. RAC SearchField's Escape handler clears the value whether or not the event was default-prevented. The `FieldInput` wrapper at `:222-233` exists exactly to let an input handler cancel field shortcuts, but Autocomplete doesn't use it.
- **Reproduction (Chromium):** type "Aus", press Escape. The input becomes `""` and `onChange('')` fires.
- **Fix:** use `FieldInput`, and call `preventDefault()` on Escape while `suggestionsOpen`. Clearing on Escape should only happen when the list is already closed.

**H4. Enter on an active suggestion submits the form with the typed text (Autocomplete)**
- **Where:** in RAC's `useAutocomplete.mjs:260-269`, Enter dispatches a click on the focused option but does not call `preventDefault`, so the browser's implicit form submit still runs. `disableAutoFocusFirst: false` (`fields.mjs:1191`) means an option is usually active.
- **Reproduction (Chromium):** in a Form with a submit button, type "Aus" and press Enter. The event log reads `submit {country:"Aus"}`, then `change "AU"`, then `select "AU"`. The form is submitted unintentionally, with the wrong value.
- **Fix:** in Autocomplete's `onKeyDown`, call `preventDefault()` on Enter when the list is open and an option is active (via `FieldInput`).

**H5. Items with a label but no value submit their array index (Autocomplete)**
- **Where:** `fields.mjs:1038-1043`. When `id` and `value` are missing, `id = String(index)` and then `value = id`.
- **Reproduction:** `items={[{label:'Melbourne'},{label:'Sydney'}]}`, select Sydney. The input shows `"1"`, `onChange('1')` fires, and FormData is `city=1`. This item shape is explicitly type-valid: `types.test.tsx:172` uses `{ label: 'Sydney' }` and `{}`.
- **Fix:** fall back to `autocompleteItemText(item)` for `value`, or require `value` or a string label in the types.

### Medium

**M1. A CheckboxGroup with a non-string label has no accessible name**
- **Where:** `fields.mjs:667` sets `aria-label` only when `label` is a string. The visible `<label>` is rendered outside `AriaCheckboxGroup` (`:670-673`), so it never gets an ID or association.
- **Verified in Chromium:** `label={<span>Toppings</span>}` produces an unnamed `group` and an orphan `<label>`. The types and `assertAccessibleName` both accept this. It contradicts the catalog claim "Expose group name".
- **Fix:** render the label inside the RAC group so `LabelContext` wires up `aria-labelledby`.

**M2. The open suggestion list is never exposed to assistive technology (Autocomplete)**
- In Chromium the input is `type=search` with `aria-autocomplete=list`, but has no `role=combobox` and never gets `aria-expanded`, open or closed.
- This contradicts the catalog line "Expose the text input, expanded suggestions, and active option".
- **Fix:** add combobox semantics plus `aria-expanded={suggestionsOpen}` on the input, or correct the claim.

**M3. Setting `errorMessage` makes the field permanently invalid (all fields; `validationProps`, `fields.mjs:313`)**
- Any `errorMessage` forces `isInvalid: true`. Under the default `native` Form, RAC then sets the input's custom validity to "Invalid value.".
- **Verified in Chromium:** `<TextField name="email" errorMessage="Enter a valid email" defaultValue="<example-email>"/>` in a Form means the form never submits.
- There is also no way to customize the message for built-in errors (required, min/max) without forcing the field invalid.
- **Fix:** show `errorMessage` only when the field is invalid, or document and type it as "currently invalid".

**M4. Server errors on TimeField and DateRangePicker don't clear when the user fixes the value**
- **Where:** `fields.mjs:297-304`, `:824-825`, `:849`, `:973-974`, `:997`. External errors are fed in as a controlled `isInvalid`.
- **Verified:** after an edit and blur, TextField and DateField clear their server error, but TimeField and DateRangePicker keep showing it.
- **Fix:** track a "server error dismissed" flag on each change, keyed to the `validationErrors` identity.

**M5. NumberField hard-codes `inputMode="decimal"` (`fields.mjs:622`)**
- This overrides RAC's device-aware value (`useNumberField.mjs:131-145`). On iPhone, the decimal keyboard has no minus key, so users can't enter negative numbers when `minValue` is unset or negative.
- **Verified by:** code reading plus SSR output.
- **Fix:** remove the override.

**M6. Selecting a suggestion writes its `value`, not its label, into the visible input (Autocomplete, `fields.mjs:1159-1161`)**
- Example: choosing "Australia" shows "AU" (seen in Chromium).
- **Fix:** decide on the contract. Either show the label text and expose `value` separately, or document that the input shows `value`.

**M7. Missing proof for several contracts**
- No controlled-mode test for any family. The test at `:388`, titled "controlled callbacks", only uses uncontrolled values and never asserts the TextField change.
- No test that required fields actually block submission (`:1152` only checks `data-required`).
- No Autocomplete keyboard (Enter/Escape/ArrowDown) or FormData test in the unit tests.
- No SearchField Escape or `onSubmit` test.
- No test for `errorMessage` without `invalid`.
- No test that server errors clear after an edit.
- No test for a non-string CheckboxGroup label.
- No FormData test for NumberField or Switch.
- No catalog-to-types-to-runtime parity test for R1.2. R1.3 has one in `r1-3-parity.test.mjs:83`; my own regex comparison found no real drift.

### Low

- **L1. SearchField Escape doesn't fire `onClear`.** `onClear` is wired only to the button (`fields.mjs:569`) and is not passed to `AriaSearchField` (`:545-553`). Escape clears the value without firing the catalogued `clear` event (verified by probe).
- **L2. TimeField submits in two formats.** A default of `09:30` submits `09:30`, but after an edit it submits `10:30:00` (`String(Time)`). Tests `:748` and `:776` assert both formats.
- **L3. CheckboxGroup's size CSS is dead.** It never sets `data-size`, so the `.muxui-checkbox-group[data-size]` rules (`base.css` ~434/455) never match. Child checkboxes size themselves, so the visual impact is low.
- **L4. Two catalog defaults are misleading.** `selected: false` (Switch) and `value: ''` (Autocomplete) are listed as defaults, but leaving the prop out means uncontrolled at runtime. Storybook already strips them.
- **L5. Fix commit `32e0f1ed` assumes Chromium behaviour.** Its blur-to-body check relies on `document.activeElement === body` during blur, and it is proven only in Chromium.

### Autocomplete dismiss fix (`32e0f1ed`)

The fix itself is sound:
- It arms the focus-restore guard on blur to the body while the list is still mounted.
- It expires the guard two frames after the list detaches, via a stable ref callback.
- It cancels the timers on clear and on unmount.
- It excludes window and tab switches.
- Its browser test covers both the used and unused guard paths.

It is **not in the reviewed commit**; it exists only on `test/autocomplete-dismiss-race`. As reviewed, `main` still has the race.
