**Overall verdict: `findings`.** Three high-severity defects make the R1.3 claim of "no actionable findings" untenable for this lane. Clicking or pressing Enter never selects anything in GridList, Tree or Table by default. TokenField throws away whatever the user types, so no token can ever be added. ComboBox lets users select and submit items marked disabled. Every finding below was confirmed by a probe, and the high ones also against React Aria's source; the GridList/Tree/Table defect also reproduces in real Chromium.

Main source is `packages/react/src/collections.mjs`. Line numbers are at 81e4c7bc. The worktree was left clean: `git status` is empty. Probes ran from an ignored scratch folder (`.claude/r13a-probe/`), which has been deleted. `pnpm generate --package @muxui/react` wrote only to ignored generated folders.

## 2. Findings, ranked by severity

### High

**H1. GridList, Tree, Table: clicking or pressing Enter never selects when nothing is selected yet.**
- **Where:** collections.mjs:653-656 (GridList `onAction`), :1012 (Table `onRowAction`), :1229 (Tree `onAction`).
- **Cause:** the wrapper always passes an action handler to React Aria, even when the consumer supplied none. React Aria then treats a press as the item's action rather than selection while the selection is empty. The relevant line is `useSelectableItem.mjs:116`: `hasPrimaryAction = allowsActions && (… !allowsSelection || manager.isEmpty)`.
- **Reproduction:** render `<GridList aria-label="g" items={[…]} onSelectionChange={log}/>`. The default `selectionMode` is `single`. Click a row: nothing is logged and `aria-selected` stays false. The same happens with Enter, and for `<Tree>` and `<Table selectionMode="single">`. Only Space selects. In multiple mode there is no selection checkbox, so a pointer user can never start a selection.
- **Verified by:**
  - a jsdom probe covering virtual click, a full mouse pointer sequence, Enter and Space;
  - a real-Chromium probe through the package's browser harness, where Playwright clicks logged no selection events for GridList, Tree or Table, Enter logged none, and Space logged `["grid",["a"]]`.
- **History:** the defect has been present since the R1.3 commit (bfd07018). ListBox had the same bug and was later fixed; its correct pattern is at collections.mjs:608-613.
- **Fix:** pass `onAction` / `onRowAction` only when the consumer provides one, mirroring ListBox's `actionProps`. Add tests that click and press Enter with an empty selection in single and multiple modes.

**H2. TokenField: typed text is thrown away, so tokens can never be added.**
- **Where:** collections.mjs:1076-1078 (`tokenValues` keeps only token segments), :1120-1126.
- **Cause:** React Aria represents typed characters as text segments in the field's value (`useTokenField.mjs` ~123-150). `handleChange` strips them and feeds back a value made only of tokens, so every keystroke is erased. The component also exposes no way to turn text into a token.
- **Further effect:** `toTokenValue` builds a new value object on every render. React Aria ends IME composition whenever the value identity changes (`useTokenField.mjs` ~97-100), so composition input also breaks.
- **Reproduction:** render `<TokenField label="Tags" defaultValue={['alpha']} name="tags" onChange={log}/>` and type "beta". The textbox still reads "alpha". `onChange` fires five times with `["alpha"]`. Enter adds nothing and the form submits `["alpha"]`.
- **Verified by:** a jsdom probe dispatching `beforeinput insertText` and `insertParagraph`.
- **Fix:** keep text segments in the uncontrolled and controlled state. Define and document a commit rule (for example Enter or comma turns the text into a token), with `onChange` still reporting only tokens. Keep the value object identity stable between renders.

**H3. ComboBox: disabled items can be selected and are submitted with the form.**
- **Where:** collections.mjs:810. `AriaListBoxItem` receives no `isDisabled`, and no `disabledKeys` are passed. `MuxUICollectionItem.disabled` is typed (`index.d.ts` `MuxUICollectionItem`) but ignored at runtime.
- **Reproduction:** `<ComboBox label="Color" name="color" items={[{id:'green',label:'Green',disabled:true}, …]} onSelect={log}/>`. Open it and click Green: `onSelect` receives `green`, the input shows "Green", and FormData holds `color=green`. The option has no `aria-disabled`.
- **Verified by:** a jsdom probe.
- **Fix:** derive `disabledKeys` from `item.disabled` and set `isDisabled` on each option, as `Select.Item` does. Add a test.

### Medium

**M1. Tabs: a disabled first tab is selected by default.**
- **Where:** collections.mjs:1025, `defaultSelectedKey: defaultValue ?? normalized[0]?.id`.
- **Reproduction:** items `[{id:'one',disabled:true,…},{id:'two',…}]`. Tab "One" gets `aria-selected="true"` and its panel is shown. React Aria does not override an explicit default key.
- **Verified by:** a jsdom probe.
- **Fix:** default to the first item that isn't disabled (or let React Aria choose by passing no default).

**M2. TagGroup: tags announce they can be removed even when they can't.**
- **Where:** collections.mjs:1037. An `onRemove` wrapper is always passed. React Aria's `useTag.mjs` ~59-62 adds the description whenever `onRemove` exists, and also wires the Delete and Backspace shortcuts.
- **Reproduction:** `<TagGroup label="Tags" items={['A','B']}/>`, then focus a tag with the keyboard. It gets `aria-describedby` pointing to "Press Delete to remove tag." and `data-allows-removing="true"`, but nothing can be removed.
- **Verified by:** a jsdom probe.
- **Fix:** pass `onRemove` to React Aria only when the consumer supplies it.

**M3. Table: wrong cell content for common column ids.**
- **Where:** collections.mjs:1014 (`row[column.id] ?? row.values?.[column.id]`) together with `normalizeItems` at :128, which injects `id`, `key`, `label`, `value` and `textValue` into every row.
- **Reproduction:** columns `name`, `value` and `label`, with rows `[{id:'r1', values:{name:'Ada', value:'42', label:'Primary'}}]`. The cells render `Ada | r1 | r1`.
- **Verified by:** a jsdom probe. The Storybook default story uses the `values` form.
- **Fix:** look up `values` first, or read from the original row object rather than the normalised one.

**M4. Missing proof that would have caught H1-H3 and M1-M2.**
- No unit or browser test clicks or presses Enter to select in GridList, Tree or Table with an empty selection.
- The Storybook plans explicitly skip the selection check for GridList and Tree: `apps/react-storybook/src/storybook-factory.mjs:1601`, `aria-selected === 'true' || channel === 'action'`, used at :1822 and :1864.
- The Tree browser test's multiple-mode case starts from a non-empty selection (`test/browser/tree-toggle-browser.test.mjs:82`, :287-293), which hides the defect.
- The TokenField tests only cover deletion and reset (r1-3-parity:789-838). The Storybook TokenField plan (storybook-factory:1847-1857) only waits for a `change` event, which fires even when the typed text is discarded.
- ComboBox has no tests for `onSelect`, `onChange`, form submission via `name`, read-only, controlled values, filtering or disabled items. The parity test at :434-472 only checks anatomy and the disabled input.
- Nothing tests a disabled first tab, or TagGroup without `onRemove`.
- **Fix:** add focused tests for each of these contracts and their failure paths, and remove the `channel === 'action'` exemption.

### Low

**L1. TokenField placeholder.** collections.mjs:1126.
- **Problem:** the placeholder renders as a permanently visible `<span>` next to the textbox. It isn't tied to the textbox (no `aria-placeholder`) and isn't hidden when tokens or text are present. The only CSS for it is in the disabled state (collections.css:2337).
- **Verified by:** a probe and grep.
- **Fix:** render it only while the field is empty, and expose it through `aria-placeholder`.

**L2. Form value ignores `item.value`.**
- **Where:** Select and ComboBox submit the normalised `id`. For `{id:'red', value:'r'}` the form gets `red` (ComboBox probe).
- **Note:** this matches the Mux "value is the id" API, but `MuxUICollectionItem.value` is typed and silently unused for forms.
- **Fix:** document that the id is what gets submitted, or submit `item.value`.

**L3. Read-only Select still opens its list.** collections.mjs:834-855.
- **Problem:** the popup opens and the user can browse it, but there is no read-only signal for assistive technology beyond `data-readonly`. The value is correctly preserved (covered by a test).
- **Fix:** consider suppressing the open, or describing the read-only state.

## 3. Claims check

- **PR #106's "fresh independent frozen-diff review with no actionable findings":** contradicted. H1, H2, H3, M1 and M2 were all present at the R1.3 commit, bfd07018 (`git show bfd07018:packages/react/src/collections.mjs`).
- **GridList catalog** ("Displays a selectable two-dimensional collection"; "Controlled and uncontrolled Core key selections are supported"): pointer and Enter selection is broken (H1).
- **Table catalog** ("selectable rows"; "Expose row selection"): pointer selection is broken (H1).
- **Tree catalog** ("nested selectable … collection"): pointer selection is broken (H1).
- **TokenField catalog:** the summary "Edits text containing inline tokens" is false (H2). The `states` list includes `invalid`, yet `invalid` is a rejected prop (r1-3-parity:68-72).
- **ComboBox:** `MuxUICollectionItem.disabled` is typed but doesn't work (H3), so the types claim behaviour the runtime doesn't have.
- **Tabs** ("Expose selected, disabled … state"): a disabled tab can be the selected one (M1).
- **TagGroup:** no false catalog claim, but its runtime semantics announce removal when none is possible (M2).
- **Authority and scope:** generated `index.mjs` exports exactly the 24 collection families (the 12 in this lane plus the 12 owned by the second reviewer), matching `src/collections.mjs`. `generated/collections.mjs` is a stamped copy differing only in its header and one import path. Nothing beyond the admitted surface is exported. Decision 0022's assistive-technology non-claim is respected.
